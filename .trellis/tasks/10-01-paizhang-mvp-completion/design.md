# 牌账 MVP 收尾设计

## 实施原则

1. 先修服务端不变量，再补 UI；客户端校验只用于即时提示，不能替代 RPC 校验。
2. 复用现有 `upsert_round_with_scores`、Sync Queue、Drift 缓存和 Realtime 刷新链路，不新增平行记分路径。
3. 回合编辑/删除使用现有 round id 和 operation id，保持幂等与离线重放顺序。
4. 结算只计算未软删除回合；金额模式必须 `sum(totals) == 0` 才生成转账。

## 分阶段方案

### Phase 1：数据正确性与生命周期

- 在 `upsert_round_with_scores` 中读取所属房间的 `scoring_mode`，金额模式拒绝非零变化合计。
- 为服务端错误提供稳定错误码，客户端将其转换成用户可读提示。
- 结束最后一个进行中牌局时把房间置为 `finished`；重新创建/开始牌局时按既有规则恢复为 `active`，由 RPC 保证权限和原子性。
- 应用原子局号迁移并补集成验证记录。

### Phase 2：回合历史和结算

- 房间页增加“回合记录”入口，按牌局展示局号、变更、备注和状态。
- 当前用户有权限时提供编辑/删除；删除显示为撤销而非物理删除。
- 新增结算页，复用 `SettlementCalculator`，显示总分、排序、转账列表和金额模式错误态。

### Phase 3：房间管理和邀请

- 将已有 RPC 接入房间设置、成员列表和邀请操作。
- 先提供复制邀请码/分享链接，再接 QR 展示和扫描，最后处理 deep link。

### Phase 4：账号、历史和发布

- 补资料编辑、个人/房间历史、分享和导出。
- 完成集成测试、离线重连测试、移动端构建和生产配置清单。
