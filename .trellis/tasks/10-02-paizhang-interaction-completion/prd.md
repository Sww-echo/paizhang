# 牌账核心逻辑与交互闭环

## 目标

让在线用户可以完整完成“登录 → 加入/创建房间 → 创建并管理牌局 → 点击头像转换积分/金额 → 修正回合 → 结束牌局 → 查看历史和结算 → 关闭房间”的核心流程。

## 本轮必须实现

### 1. 牌局生命周期

- 创建牌局后支持明确的“开始牌局”状态，不因第二步失败留下无法处理的草稿。
- 草稿牌局支持开始、取消/删除。
- 草稿和进行中牌局可重命名；已结束牌局支持房主确认后重新打开，再修正回合。
- 进行中牌局结束前需要确认。
- 结束后的牌局只读，不能继续录入、编辑或撤销。
- 牌局列表正确显示草稿、进行中、已结束状态。

### 2. 房间关闭投票

- 房间内任一有效成员可以发起/参与关闭投票。
- 每个成员对当前关闭提案只有一票，可修改同意/不同意。
- 同意票数严格大于有效成员数的一半时，房间关闭并进入归档状态。
- 有进行中牌局时不能关闭，必须先结束所有进行中牌局。
- 投票面板展示有效成员数、同意票数、当前用户投票状态和关闭结果。
- 房间关闭后禁止创建牌局、录入、修改回合和成员管理，但允许查看历史与结算。
- 房主可修改房间名称和玩法；已有回合后不可改变记分模式。
- 关闭（归档）和解散（保留历史）均走同一投票门槛，不能直接绕过投票。
- 投票启动后固定本轮成员；成员变化或开始牌局取消本轮投票，24 小时过期，避免沿用旧票。

### 3. 历史查询

- 用户离开房间后仍可查看自己参与期间的房间、牌局、回合和结算。
- 当前房间列表只显示仍在参与的房间；历史页单独显示已离开房间。
- 被移除成员进入历史页时仍能查看历史数据，但不能继续操作房间。

### 4. 头像资料

- 个人页支持选择和修改预设头像。
- 支持上传、替换和删除图片头像，失败保留原头像。
- 头像保存到 Auth metadata 和 profiles。
- 房间成员、房间管理、历史/结算页面统一展示头像或首字母回退。

### 5. 登录和状态交互

- 验证码登录支持重新发送、倒计时和修改邮箱/手机号。
- 被移除、房间已关闭、房间访问失效时显示明确原因并提供返回入口。
- 重要提交操作有 loading 和防重复提交。
- 回合备注、非零分数校验、提交确认摘要、成功反馈、多端冲突提示和状态中文化。

## 明确延期

- 邀请列表、撤销、刷新、有效期和邀请系统分享增强。
- 离线快照读取、队列管理、失败操作重试 UI。
- 账号删除、数据导出、通知设置。
- 移动端发布配置和真机验收。

## 验收标准

- 草稿牌局不会出现无法开始或无法清理的死状态。
- 结束牌局后所有写操作入口均不可用，并且服务端拒绝越权写入。
- 关闭投票在 2 人房间需要 2 票，在 3 人房间需要 2 票，在 4 人房间需要 3 票。
- 房间关闭后成员可以进入历史和结算，但不能创建牌局或修改记录。
- 离开或被移除后，历史页仍能加载原房间的历史快照。
- 修改头像后重新进入房间，所有成员看到一致头像。
- 验证码可重新发送，重复点击不会发起重复请求。
